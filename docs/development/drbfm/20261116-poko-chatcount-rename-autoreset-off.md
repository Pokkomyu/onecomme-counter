# DRBFM: poko-chatcount 名前を Poko-ChatCount に変更・自動リセットの既定を OFF に変更(追加: 全リセットの確認欄・テーマの選択表示)

## 1. 変更概要

- 背景 / 目的:
  - 道具の名前を「Poko-ChatCount」にする(devuser 決定 2026-11-16)。
  - 配信者の要望: 数を見て報告するときに自分でリセットしたい。DbD のクラッシュで OBS ごと落ちて再配信すると、
    新しい配信として 0 に戻ってしまう。そこで「配信が始まったら自動で 0 に戻す」の既定を OFF にする。
- バージョン区分と根拠: **patch(0.2.0 → 0.2.1)**。新しい道具・仕組みを足さない。表に出る名前と、既にある設定 1 つの既定値を変えるだけで、
  保存形式(schema 2)・保存キー・数え方・リセットの判定は 0.2.0 のまま。保存済みの設定はそのまま読める。
- devuser が決めたこと(2026-11-16):
  1. 名前を変えるのは表に出る所だけ: zip 内のフォルダ名、zip 名、`<title>` と冒頭コメント、README、AGENTS.md、package.json の description、
     test-asset-lifecycle-policy.md の repo 表記、Release の題。
  2. GitHub の repo 名 `onecomme-counter` と保存キー `onecomme-generic-counter-v1` は変えない。
  3. `autoReset` の既定を OFF にする。保存済みの値があればそちらを使う(0.2.0 を使っていた人は ON のまま。強制では変えない)。
  4. (追加・同日)配信者から「全リセットが前からずっと押せない」と報告。原因は `confirm()`。OBS のブラウザソースは JS のダイアログを出せず、
     `confirm()` が常に false を返すので、押しても何も起きない。押すとその場に「本当に 0 に戻しますか? [0 に戻す] [やめる]」を出す方式に変え、
     0.2.1 に入れる(未公開の版なので版は上げない)。
  5. (追加・同日)テーマのボタンも、いま使っているテーマが分かるように色を付ける。選択中の色(`.tg.on`、今は緑 `--ok`)をピンク(宇宙猫ピンク `#ff62c9`)にする。
     接続状態の緑(`#status.ok`)は変えない。
  - 4・5 を足しても区分は **patch**: 既にある操作の不具合修正と見た目の調整で、保存形式・保存キー・数え方は変えない。テーマ名は保存せず、色の値で判定する。
- 変更内容:
  - `template/index.html`: `<title>`(L5)、冒頭コメント(L7)、`CONFIG.version`(L158)、`CONFIG.defaults.autoReset`(L174)。この 4 か所だけ。
  - `README.md`: 題、入れ方、自動リセットの説明、注意、0.2.0 以前から入れ替える人向けの案内。
  - `AGENTS.md` L3、`package.json`(description・version)、`package-lock.json`(version 2 か所)、
    `docs/development/test-asset-lifecycle-policy.md` L7・L9、`docs/README.md` の索引。
  - `template/index.html`(追加 4・5): 全リセットの `confirm()` を確認欄に置き換える。`:root` に `--sel`、`.tg.on` を `--sel` に。
    `refreshUI()` でテーマのボタンに `on` を付ける(`state.colors` が `THEMES[名]` と `CSS_VARS` の全キーで一致したら)。
  - `tests/occ.spec.js`: 既定 ON を前提にした試験の前提を直す、新しい試験を足す。ダイアログを自動で OK する処理をやめ、ダイアログが出たら失敗にする。
  - 配布物(repo の外、handoff で作る): zip 名 `Poko-ChatCount-0.2.1.zip`、中のフォルダ `Poko-ChatCount/`、Release の題。
- 影響範囲候補: 初期値(`freshState`)、保存値の読み込み(`load`)、配信開始の処理(`newStream`)、操作パネルのチェック欄、
  あいさつ済み・フォロー済みの記録が消えるタイミング、わんコメのテンプレート一覧名と配信 URL、OBS のブラウザソース、README の案内、既存の自動試験。

## 5. メモ

- 省略した試験と理由: 行 16(過去の記録を変えない)は差分の確認で足りるため試験項目にしない。
- zip を作る手順は repo にない。0.2.0 と同じく handoff の `run.sh` で作る(TC-OCC-090 はそこで確認する)。
- 全リセットの不具合(行 18)が 0.2.0 まで見逃された理由: 試験がページのダイアログを自動で OK していたため、`confirm()` が OBS で常に false になることを試験では再現できなかった。行 19 で、ダイアログが出たら失敗にする。
- 0.2.0 を使っている間に 0 に戻したいときは、「−1」で減らすか、自動リセットのチェックを入れて配信を始め直す(配信者への案内)。
- 残リスク:
  - 0.2.0 を使っていた人が案内を読まずに入れ替えると、ON のまま使い続ける(挙動は 0.2.0 と同じで、悪くはならない)。
  - わんコメに旧「色々カウンター」のフォルダが残る。害はないが、旧ソースを OBS に残すと数が飛ぶ(README で案内)。
  - 既定 OFF で全リセットを忘れると、前の配信の数に足され続ける(要望どおりの挙動。README に書く)。
